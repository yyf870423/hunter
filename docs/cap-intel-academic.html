学术 & 专利情报

AI / 算法 / 研发岗的候选人，论文和专利就是简历之外的硬核证据。 Hunter 接入全球学术库（OpenAlex），支持国知局专利 Excel 导入， 论文 / 专利双向自动关联到候选人，做岗位匹配时还会作为额外的判断维度。

产品里对应左侧 sidebar「寻访（找人）」分组下的「学术搜索」。 论文和专利的管理入口也通过工作台或候选人详情页跳转进入。

三个相关页面，各管一件事

  • 学术搜索：从 OpenAlex 全球学术库按机构/时间搜论文，把候选人对标公司的研究产出捞回来
  • 论文管理：库里所有论文的统一视图——搜索、上传 PDF/DOCX、翻译未译标题
  • 专利管理：从国知局下载的专利 Excel 导入，统一管理

三个页面是同一池数据的不同入口：在哪上传都进同一个论文 / 专利库，关联候选人时也共用。

学术搜索：按机构和时间捞论文

日常场景：客户想找「某个对标公司近一年发了哪些大模型论文」的人。 过去你要手动翻 OpenReview / arxiv / 论文数据库，现在 Hunter 直接在学术搜索页一次搞定。

  1. 左侧 sidebar 进入「学术搜索」
  2. 添加机构（必填，可勾多个 = OR 命中）

    点「+ 添加机构」，搜索框里输入机构名（中文或英文均可），比如「字节」「Microsoft」「Tsinghua」。 勾选要查的机构，可以一次选多个，Hunter 会用 OR 条件命中。

  3. 选时间区间（必填）

    开始月 + 结束月。结束月留空 = 至今。 提供快捷按钮：本月 / 3 个月前 / 1 年前。 窄一点的时间区间（如近 6 个月、近 1 年）通常更聚焦。

  4. 跑搜索

    Hunter 调 OpenAlex 接口，返回符合条件的论文列表。 默认上限 5000 篇（v0.10.2 调高），覆盖绝大多数实际场景。

  5. 结果里看作者机构展示

    每篇论文展示标题、作者、作者机构、年份。 重点看作者列表——这些作者就是你的潜在候选人。

左侧 sidebar →「学术搜索」— 研究方向 + 机构表单 + 任务结果

研究方向聚合

学术搜索页顶部有研究方向 tag 列表（Top 20 方向 + 论文数）。 点某个方向的 tag，能看到这个方向下所有论文。 点右侧「全部方向 →」看完整的方向列表。

研究方向是 Hunter 从论文标题 / 摘要自动聚类出来的， 随着你库里论文增加会自动更新—— 不用你手动维护。

论文管理：库内所有论文的视图

论文管理页有两个 Tab：论文列表 / 导入论文。

论文列表 Tab

  • 搜索框：placeholder「搜索论文标题（支持中文）或作者姓名」—— 中英文标题都能搜
  • 「翻译全部未译」按钮：库里所有中文标题或中文摘要为空的论文，一次性翻译。 点击弹出 modal 显示「N 篇论文待翻译」+ 确认
  • 论文卡片：标题（中英文）、作者列表（命中候选人会标蓝高亮）、年份、机构、关联候选人
  • 分页

导入论文 Tab

上传论文 PDF / DOCX 文件——Hunter 自动提取标题、作者、摘要、机构等。 可同时选多个文件。

  • 状态过滤 pills：全部 / 进行中 / 已完成 / 失败
  • 失败 ≥ 2 时上方出现「全部重试」按钮
中文标题翻译怎么用

OpenAlex 返回的论文标题大多是英文；你给国内客户汇报时需要中文标题—— 「翻译全部未译」一次性把库里所有未译的中文标题/摘要补上，下次就能直接给客户中文版本。

专利管理：导入国知局 Excel

专利管理页有两个 Tab：专利列表 / 导入专利。

专利列表 Tab

  • 搜索框：placeholder「搜索标题、专利号、发明人」
  • 专利卡片：标题、专利号、发明人列表（命中候选人标蓝）、申请人 / 权利人（取代旧版专利号显示）、申请日
  • 分页

导入专利 Tab

  1. 从国知局下载专利 Excel

    国知局（国家知识产权局）官网的专利检索系统支持按检索条件导出 Excel。 导出 13 列标准格式（申请号、发明人、摘要等）。

  2. 在「导入专利」Tab 上传 .xlsx

    支持多文件同时上传。Hunter 自动解析每行专利信息入库。

  3. 等待解析完成

    处理记录表格显示每个文件的状态。已知问题：如果专利申请号缺失，Hunter 会用 hash id 替代（避免入库失败）。

候选人与论文/专利的双向关联

这是学术情报的核心价值——不是「拥有一堆论文」，而是「论文知道是谁写的，候选人知道发过什么」。

自动关联

每次有新论文或新专利入库，Hunter 会用作者/发明人姓名去候选人库匹配：

  • 命中候选人 → 自动关联
  • 姓名常见、不确定是哪个候选人 → 进入待确认（与「多重简历比对」类似的人工拍板流程）
  • 库里没找到 → 论文 / 专利保留在库里，未来如果这个作者作为候选人入库，会自动回填关联

在论文/专利详情页，命中候选人的作者姓名会标蓝， 点击直接跳到那位候选人的详情页。

从候选人视角看 ta 的论文专利

进入任意候选人详情页，下方有一个独立 section 展示 ta 的论文和专利：

  • 论文列表（默认显示 5 篇，点「查看全部」打开候选人学术页的论文 Tab）
  • 专利列表（同样 5 篇预览，点「查看全部」打开候选人学术页的专利 Tab）

候选人学术页有两个 Tab 可切换： 论文（N）/ 专利（N）， 显示这位候选人的全部论文 / 专利。

论文专利会进岗位匹配评估

岗位智能匹配做评分时，论文数 / 专利数 + 代表作会作为额外的评估维度—— 尤其对学术圈 / 研发岗，候选人有 3 篇顶会一作 vs. 没有，分数会有明显差异。

最佳实践

怎么用学术搜索做 mapping 的前置情报

想给客户建一张「字节大模型团队」mapping？先到学术搜索： 机构选「ByteDance」，时间近 1 年，研究方向选「大模型」相关—— 搜出的论文作者列表就是这个团队的核心成员。 把这些作者拉进候选人库（或确认已在库内），再回去建 mapping，节点就有了具体的人。

姓名常见的候选人，先关联论文/专利

「张伟」「王芳」这类常见姓名，仅凭名字会有大量同名干扰—— 如果你能在候选人详情页里手动确认 ta 的论文/专利， 后续「档案焕新」「岗位匹配」都能用这层身份锚点排除同名干扰，准确度大幅提升。

常见提示

学术搜索结果偏少

常见原因：① 时间区间太窄（如只选了 1 个月）； ② 机构名拼写不对（OpenAlex 用机构标准名，搜索时输入部分关键词尝试匹配）。 可以先放宽时间区间到 1 年，再逐步收紧。

专利 Excel 上传失败：列名不对

确保是从国知局下载的标准 Excel（13 列：申请号、发明人、摘要等）。 非国知局导出的格式 Hunter 不保证兼容—— 可以打开 Excel 检查列名，必要时手动改成 13 列标准格式。

论文翻译"全部翻译"无响应

「翻译全部未译」是后台任务，翻译几百篇可能需要几分钟。 页面点完按钮 modal 关闭后任务在后台跑，几分钟后回来刷新即可看到中文标题/摘要。 进度可在论文列表里直接观察（已翻译的会更新）。
