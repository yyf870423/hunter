自动寻访

为岗位配好关键词和筛选条件，晚上让 Hunter 替你在招聘平台上跑寻访—— 打开候选人详情、按你的标准初筛、把符合的候选人草稿入到待审池。 第二天早上你花二十分钟过一遍待审池，确认入库即可。

产品里对应左侧导航「岗位（需求）」分组下的「人才寻访」（Beta）。 配置入口是岗位详情页 → 寻访配置；总览页是「人才寻访」。

这是 Beta 功能

自动寻访目前处于 Beta 阶段，能力还在打磨中—— 平台覆盖、抓取稳定性和识别准确度都在持续完善，偶尔会遇到需要登录、被限流或漏抓的情况。 寻访到的候选人都先进待审池，由你逐个确认后才入库，不会擅自写进你的候选人库，可以放心试用。 用下来有问题或建议，欢迎随时反馈给我们。

支持的平台

当前 Beta 阶段，寻访支持两类平台：

  • 猎聘 + 脉脉：已接入的两大主力渠道，默认开启。两个平台可以同时勾选、同时跑，各自独立配置关键词和筛选条件。
  • LinkedIn / BOSS 直聘：已在平台列表里占位，默认关闭、暂未接入。等接通后会自动变为可勾选（每接通一个，你就多一个不眠不休的寻访伙伴）。
每个平台要先各自登录账号

自动寻访用你自己的招聘平台账号跑，所以第一次用要先在 Hunter 里登录对应平台的账号—— 用猎聘就登录猎聘，用脉脉就登录脉脉，两个平台的登录状态各自独立。 登录入口在配置页的「平台」板块，点某个平台的「启用并登录」会弹出该平台的登录窗口， 完成后状态会变成「正常」。你打算跑几个平台，就把哪几个登录到「正常」。

配置一次寻访

每次寻访绑定一个具体岗位。从岗位详情页进入「寻访配置」，先选平台，再为每个勾选的平台各自填一遍配置。 猎聘和脉脉的关键词、筛选条件、停止条件、审核门槛都各自独立—— 页面顶部有「猎聘配置 / 脉脉配置」两个标签页，切换过去分别填即可。

  1. 选平台

    勾选你要跑的平台——猎聘、脉脉可以只勾一个，也可以两个都勾（LinkedIn / BOSS 直聘暂未接入、置灰）。 如果某平台状态显示「需要登录」「限流」「验证码」「异常」，先按卡片上的按钮提示处理—— 只要有一个勾选的平台状态不是「正常」，就不能开始寻访。

  2. 设关键词（每个平台各设一组）

    1-5 条关键词组合，每行最多 5 个词。每行作为该平台的一次搜索。 可以手动写；猎聘那栏还能点「使用 AI 生成关键词」根据岗位 JD 给你一组候选关键词。 此外，如果这个岗位跑过「岗位 Agent」，Agent 整理出的关键词会作为初始值自动带入寻访配置（详见 岗位 Agent）。脉脉每行还能单独设「满足所有 / 满足任一」的词间关系。

  3. 设筛选条件（对应各平台的搜索筛选项）

    猎聘：职位名称 / 公司名称（含范围：全部 / 当前 / 过往）· 城市 · 工作年限（不限 / 3-5 年 / 5-10 年 / 10 年以上 / 自定义）· 学历（多选）· 排序（推荐 / 最近活跃 / 更新时间）· 求职状态（多选）。 还有三个开关：隐藏已查看 / 隐藏已沟通 / 隐藏已获取联系方式—— 默认勾后两个，避免你重复消耗精力在已经接触过的候选人上。

    脉脉：城市 · 学历 · 工作年限 · 就职公司 · 职位名称 · 毕业学校 · 年龄 · 期望月薪； 另有「从结果中筛选」的进阶开关（公开求职意向 / 近期有动向 / 有简历附件 / 有过意向）。 两个平台的筛选条件互不影响，按各自平台的字段填。

  4. 设「打开详情规则」（猎聘的列表初筛）

    在猎聘的搜索结果列表上，什么条件的候选人值得打开详情看。 包括：年龄区间、学历多选、城市。 这一步只看列表卡片显示的字段做硬规则筛选、速度快、量大不心疼。

  5. 设「停止条件」（满足任一即停，每个平台单独累计）

    数字上限，哪个先到哪个停。猎聘有三个、脉脉有两个：

    • 已初筛数上限（猎聘，默认 500）：从搜索列表判断过多少候选人卡片
    • 已寻访数上限（默认 100）：打开过多少候选人详情
    • 待确认数上限（默认 30）：放进待审池等你看的人数

    这些数字是寻访的「天花板」，避免任务跑飞。第一次跑建议保留默认，跑完一次有感觉再调。

  6. 设「审核」入库门槛

    匹配分数 ≥ N 分（默认 60）的候选人进入待确认池，其他直接丢弃不打扰你。 想严格一点就调到 70-80，想多看一些就降到 50-60。这一项也是每个平台各自设。

  7. 点右上角「开始寻访」

    任务进入后台运行。勾了几个平台就同时起几路寻访。你可以离开这个页面，去做候选人管理、Mapping 都行。

岗位详情页 →「寻访配置」— 先选平台，再切换「猎聘配置 / 脉脉配置」分别填关键词/筛选条件等

寻访在跑时你能看什么

左侧导航进入「人才寻访」总览页。从上到下：

  • 3 个 关键指标：今日已查看详情 · 今日待确认候选人 · 今日已入库候选人
  • 异常处理入口（出现时）：如果任务在某个页面遇到提取异常或运行异常， 会出现红色横幅「N 个样本待处理」+「处理异常」按钮。异常状态下任务自动暂停， 不会继续打开详情或触达候选人——你可以放心去处理而不担心持续消耗
  • 3 个标签页：已寻访 / 正在寻访 / 全部
  • 任务表格：每行一个寻访任务，显示岗位、状态徽章、待确认数、已入库数、操作。 一个岗位如果同时跑了猎聘和脉脉，会在该行下方展开各平台的子状态，方便你分别看哪个平台跑到哪

任务状态说明

  • 排队中：等待资源（如平台限流冷却中）
  • 寻访中：正在跑寻访
  • 寻访结束：达到停止条件或自然结束，且没有待确认项
  • 等待复核：寻访结束、且还有待确认的候选人没看
  • 运行异常 / 认证失败：需要你处理（点开任务进异常处理流程）
  • 已停止：你手动停止

待审池：第二天早上花 20 分钟过一遍

这是自动寻访最重要的一步——AI 帮你筛过的候选人不会直接进库， 都暂存在待审池里等你拍板。

寻访结果页结构

从任务表格点某个任务进入「寻访结果」页面。顶部统计：

  • 已导入：你点过「加入系统」的候选人数
  • 待确认：等你看的候选人数
  • 不合适：你标过「不合适」的
  • 全部：以上三类合计（已导入 + 待确认 + 不合适）

表格每行一条候选人草稿，列依次是：候选人（姓名 + 职位/公司/年龄/城市）· 来源（猎聘 / 脉脉）· 分数 · 身份完整度（姓名是否完整）· 联系方式（手机号可见 / 打码 / 未获取）· 审核状态 · 操作。 操作列按状态给不同按钮：待确认给「加入系统 / 不合适」，疑似重复给「处理重复 / 不合适」， 已导入给「查看详情」，标过不合适的给「恢复审核」。

寻访结果页 — 候选人草稿 + 加入系统/不合适 操作

逐条审核：怎么操作

点候选人姓名进入审核详情页。详情页展示：

  • 从平台（猎聘 / 脉脉）抓到的完整信息：基本信息、工作经历、项目经历、教育背景、技能标签、行业标签等草稿
  • 右侧的 AI 评估摘要、岗位匹配分数、匹配理由 / 风险点
  • 寻访来源卡片：平台、搜索关键词、查看时间、来源 URL；脉脉抓到的简历会以「附件简历」形式列出，可点开查看
  • 如果有疑似重复（库里可能已有同人），会单独提示，需先处理

顶部核心操作按钮（随状态显隐）：

  1. 「加入系统」（蓝色主按钮）

    确认这位候选人值得入库 → 草稿转正式记录入候选人库，并写入该岗位的匹配结果。 如果检测到疑似重复，会引导你先决定「同一个人 → 合并」或「不是 → 各自独立」。

  2. 「编辑」

    入库前可以直接就地修改草稿——基本信息、教育、工作经历、项目、技能、行业标签都能改， 保存后入库前会重新检查一次重复候选人。

  3. 「上传简历」

    从其他渠道拿到这位候选人的简历（PDF/DOCX），可直接传上去覆盖草稿信息，入库后档案更完整； 寻访来源、来源 URL、当前岗位匹配记录不受影响。

  4. 「不合适」

    这位不符合你的标准 → 标记为「不合适」。 不会被继续补充、触达、查重或入库， 但保留在结果里，未来反悔可以「恢复审核」。

  5. 「恢复审核」（标过不合适后出现）

    把候选人从「不合适」恢复回「待审核」状态，重新决定。

联系方式默认遮挡

待审池里的候选人，手机和邮箱默认遮挡，看到的是简介和经历。 点「加入系统」入库后，平台上的联系方式才会同步进候选人档案。 这是为了让你先按业务判断再决定是否消耗平台的「看号」配额。

上传简历会覆盖草稿，来源信息保留

在审核详情页点「上传简历」补一份 PDF/DOCX 后，Hunter 会用简历解析结果覆盖 基本信息、教育、工作、项目、技能/行业标签和 AI 摘要；而寻访来源、来源 URL、当前岗位匹配记录不受影响。 解析期间该草稿暂时不可编辑，完成后自动刷新。

异常和限流怎么处理

招聘平台的反爬、限流、需要验证码——这些异常会让寻访任务主动暂停， 不会一直撞墙浪费配额。处理方式：

  • 需要登录：点配置页对应平台卡片的「登录」按钮重新登录（猎聘、脉脉各自登录）
  • 验证码：点「打开平台处理」在平台上完成验证后回 Hunter 点「检查状态」
  • 限流：等冷却时间（一般几分钟到几小时），Hunter 会自动恢复
  • 页面提取异常：「人才寻访」总览页顶部会出现红色横幅「N 个样本待处理」， 点「处理异常」进入异常处理弹窗，可点「查看样本」跳到错误样本页

错误样本页把每一条异常的证据（失败字段、失败原因、页面 URL、页面文本、DOM 片段、抽取结果 JSON、截图）都记下来。 你可以逐条把样本标为「处理中」或「已处理」，也可以「导出样本」 （默认导出「待处理 / 处理中」的样本，敏感信息如登录态、Cookie、手机号会自动脱敏）打包发给我们排查。 当前版本不做自动修复：系统只负责记录异常样本，人工处理完后再从配置页重启任务。

最佳实践

「下班开跑，早上审入库」的节奏

自动寻访最好的用法是把它和你的工作时间错开—— 上午配好任务、下班前点开始，让它整夜跑； 第二天上午第一件事过待审池，决定哪些入库哪些拒绝。 这样不打断你的日常工作，但每天醒来都有「昨夜捞的新候选人」等你审。

同一个岗位多关键词组合

一个岗位往往可以拆出 2-3 个不同的关键词组合（比如「推荐算法 工程师」「召回排序」「推荐系统 中级」）—— 这些可能在不同搜索条件下命中不同的人。 充分利用 5 条关键词的额度，能让寻访覆盖面广得多。

入库门槛先松后严

第一次跑某个岗位时不知道分数标准，建议把入库门槛设到 50 分跑一次—— 看待审池里 50-60 分、60-70 分、70+ 分的候选人质量分别如何， 找到你这个岗位的「该不该看」边界，下次再调到合适的阈值。

常见提示

「开始寻访」按钮点不下去

按钮旁会显示原因：通常是某个勾选的平台状态不是「正常」（需要登录 / 限流 / 验证码 / 异常）、 一个可用平台都没选，或关键词留空。 注意只要有一个勾选平台没就绪，按钮就会锁住，按提示先处理即可。

平台登录窗口关掉了怎么办

登录窗口不小心关了 / 卡住了——回配置页对应平台卡片点「检查状态」， 状态会刷新成真实情况；如仍未登录，点「启用并登录」重新打开登录窗口。 猎聘、脉脉互不影响，哪个没就绪就单独处理哪个。

待审池里候选人质量差

常见原因：① 关键词太宽（如只填「算法」，命中泛滥）； ② 筛选条件太松（不限年限、不限学历）； ③ 入库门槛太低（≥ 50 分进了一堆边缘人）。 到配置页调紧任意一项，下次跑就准多了。

不要长期跑无人看的寻访

待审池积压到几百人不审是浪费——这些候选人在平台上可能很快被别人联系。 保持「跑一次审一次」的节奏， 一次任务完成后第二天就过完待审池，长期效率最高。
